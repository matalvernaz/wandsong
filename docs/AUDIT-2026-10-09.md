Wandsong audit, October 9, 2026. Baseline: `3d99313f0c376150b5c0edec0d1699b30e9b8787`.

The audit found **20 actionable defects: six high, thirteen medium and one low priority**.
Eighteen were reproduced in isolated tests; two were confirmed from source control flow
or documented API behavior. The highest priorities are preserving files during setup and
uninstall, preventing incorrect menu actions, and correcting load handling. Passing the
existing tests does not cover these failure cases.

High means possible loss of existing installation files, an unintended menu action, or a
major accessibility/stability failure under the stated trigger. Medium means a broken
feature, incorrect state or an integrity weakness with narrower conditions. Low means an
inconsistency with an available working alternative. These are engineering priorities,
not security vulnerability scores.

The review covered the Lua runtime, configuration and persistence, navigation, menus,
combat and interaction cues, spell lessons, subtitle/audio-description scheduling, the
native bridges and speech helper, installer/update/uninstall logic, release/deployment
tools, and CI. Generated description/preset data was checked through the existing tests;
the visual accuracy of every description and preset was not independently reviewed.
The vendored Lua implementation and third-party binary dependencies were not subjected
to a separate upstream security audit.

Validation completed on Windows:

- Existing offline suite: **36 passed, 0 failed**.
- Existing installer suite: **28 checks, 0 failed**, against a freshly built installer and fake game folders.
- Native modules and Lua host, speech helper, and a fresh Release installer all built successfully.
- All **16 previously tracked PowerShell scripts** parsed; all **17 previously tracked Python scripts** passed syntax parsing.
- **13 additional Lua scenarios** reproduced runtime defects using fake game objects and isolated settings.
- **Six additional installer scenarios** reproduced five findings in disposable fake installations.

There was no live-game session, deployment, real input injection, save modification or
release publication. Consequently, the runtime reproductions prove the stated logic
errors; they do not establish how frequently the game produces each triggering state.
No native game crash or real save deletion is claimed. Production implementation files
were left unchanged. Additions are this report, its evidence scripts and local audit
artifacts. The temporary `installer/build-audit` build directory was removed before the
first fix batch was committed.

The reproducible evidence is in
[tools/audit_2026_10_09/README.md](../tools/audit_2026_10_09/README.md).
Local results, not in the repository, were written to
`dist/audit-2026-10-09/runtime-results.txt` and `dist/audit-2026-10-09/installer-results.json`.

1. **A01 — High: failed uninstall restoration deletes the only backup and reports success.**

   Source: [installer/src/main.cpp:552](https://github.com/matalvernaz/wandsong/blob/3d99313f0c376150b5c0edec0d1699b30e9b8787/installer/src/main.cpp#L552),
   particularly the unchecked restore at line 562 and backup deletion at line 564.

   Uninstall ignores file removal and restore errors, then deletes the backup directory
   and manifest and announces that the original game folder was restored. In the
   `locked_restore` probe, the installed fake `dwmapi.dll` was held open without write/delete
   sharing. Uninstall exited 0, did not restore the original loader, and deleted both its
   backup and installation record. This is verified data loss inside the fake installation.

   Preserve each backup until its restoration succeeds and is verified. Return failure
   with the affected paths and retain a retryable journal/manifest. Initial backup failures
   at lines 475-480 must also stop installation before the original is overwritten.
   Regression coverage should include locked destinations, failed backup creation and
   successful retry after the lock is released.

2. **A02 — High: shared UE4SS files are overwritten without backup and removed on uninstall.**

   Source: [installer/src/main.cpp:475](https://github.com/matalvernaz/wandsong/blob/3d99313f0c376150b5c0edec0d1699b30e9b8787/installer/src/main.cpp#L475)
   and [tools/build_release.ps1:90](https://github.com/matalvernaz/wandsong/blob/3d99313f0c376150b5c0edec0d1699b30e9b8787/tools/build_release.ps1#L90).

   Setup backs up only four predefined paths, but the release also installs files under
   `Mods/shared` and `Mods/Keybinds`. Existing files at those paths are overwritten and
   recorded as Wandsong-owned files. In `shared_file`, a pre-existing customized
   `Mods/Keybinds/Scripts/main.lua` was overwritten; uninstall then deleted it and returned
   success. The original was never backed up.

   Track ownership and previous contents for every destination that setup changes.
   Restore pre-existing files on uninstall and remove only files the installation created.
   Exercise customized shared files, updates after installation, and unrelated files
   added later. Keep this accounting separate from the user's Wandsong settings policy.

3. **A03 — High: installation is not transactional and can leave an enabled, unrecorded partial installation.**

   Source: [installer/src/main.cpp:487](https://github.com/matalvernaz/wandsong/blob/3d99313f0c376150b5c0edec0d1699b30e9b8787/installer/src/main.cpp#L487)
   and [installer/src/main.cpp:529](https://github.com/matalvernaz/wandsong/blob/3d99313f0c376150b5c0edec0d1699b30e9b8787/installer/src/main.cpp#L529).

   Files are written directly into the game directory. A late write failure returns
   immediately without rolling back earlier writes; the manifest is written only at the
   end and its stream status is never checked. In `partial_install`, a deliberately blocked
   later destination caused exit 1 after the loader and mod entry point had been installed.
   No manifest existed, and uninstall refused to remove the partial installation.
   In `manifest_error`, making the manifest path a directory produced exit 0 and the normal
   success announcement, despite there being no manifest file.

   Validate required package contents and destinations first, stage the payload, record
   changes durably, and commit the loader last. Check backup, settings, manifest and close
   operations, with rollback or an explicit resumable recovery state on failure. Test
   failures at the beginning, middle and end, including full disk and access denial.

4. **A04 — High: a button can resolve to an unrelated button's click handler.**

   Source: [menus.lua:1305](https://github.com/matalvernaz/wandsong/blob/3d99313f0c376150b5c0edec0d1699b30e9b8787/mod/Wandsong/Scripts/menus.lua#L1305)
   and the caller at [menus.lua:1433](https://github.com/matalvernaz/wandsong/blob/3d99313f0c376150b5c0edec0d1699b30e9b8787/mod/Wandsong/Scripts/menus.lua#L1433).

   `bound_event` records the first function containing `OnButtonClickedEvent` as a fallback
   and returns it when the exact button-name binding is absent. This result takes
   precedence over the native delegate fallback. The `wrong_handler` probe gave a
   `ContinueButton` an owner with only a `DeleteSave` binding: the resolver returned the
   delete binding. No real menu action or save deletion was performed.

   Require a verified binding to the selected button. Use that button's actual delegate
   when available; otherwise say that activation is unavailable. Never select a handler
   merely because its signature matches. Test multiple buttons, inherited handlers,
   unmatched names and an absent delegate; an unmatched button must invoke nothing.

5. **A05 — High: a menu without Blueprint ticks can be treated as an endless load.**

   Source: [dispatch.lua:260](https://github.com/matalvernaz/wandsong/blob/3d99313f0c376150b5c0edec0d1699b30e9b8787/mod/Wandsong/Scripts/dispatch.lua#L260)
   and [dispatch.lua:41](https://github.com/matalvernaz/wandsong/blob/3d99313f0c376150b5c0edec0d1699b30e9b8787/mod/Wandsong/Scripts/dispatch.lua#L41).

   After one Blueprint tick has been observed, a gap longer than 1.5 seconds causes every
   async timer tick to extend `state.loading` by another two seconds. This ignores the
   known `state.ui_blocker`, although `held()` explicitly permits menu work during a tick
   gap. In `menu_stall`, a paused menu with no further Blueprint ticks stayed loading for
   the entire seven-second simulation, and its queued menu action never executed.

   Distinguish a known paused/menu state from a suspected world load. Preserve the world
   object barrier during uncertain gaps while allowing safe menu/speech work. Add a test
   with real hook ticks followed by a menu lasting well beyond 1.5 seconds, plus the
   existing load/freeze tests. Live testing must confirm the actual tick patterns of pause,
   failure and other modal screens.

6. **A06 — High: the crash-paused world path still queries objects during a marked load.**

   Source: [world.lua:282](https://github.com/matalvernaz/wandsong/blob/3d99313f0c376150b5c0edec0d1699b30e9b8787/mod/Wandsong/Scripts/world.lua#L282).

   `gate_check` processes `not enabled` before the `state.loading()` guard. The disabled
   branch calls `ui_blocker()` when `dispatch.ticking()` is true, so it can resolve or
   search for the UI manager while a load is explicitly marked. The
   `disabled_world_loading` probe started with an isolated crash-fuse flag and an active
   loading state and observed six object searches. The enabled branch correctly avoids
   those searches. A native crash was not reproduced, but this defeats the project's
   explicit load barrier in its recovery mode.

   Put the no-object-access load guard ahead of both enabled and disabled world handling.
   Keep recovery announcements object-free. Test crash-paused startup, manual load marks
   while ticks still arrive, and subsequent recovery; assert zero object queries during
   every marked load.

7. **A07 — Medium: the online update path cannot request elevation for a protected game folder.**

   Source: [installer/src/main.cpp:747](https://github.com/matalvernaz/wandsong/blob/3d99313f0c376150b5c0edec0d1699b30e9b8787/installer/src/main.cpp#L747)
   and [installer/src/main.cpp:860](https://github.com/matalvernaz/wandsong/blob/3d99313f0c376150b5c0edec0d1699b30e9b8787/installer/src/main.cpp#L860).

   An interactive online update starts the downloaded installer with `--install`. That
   child sets `interactive` to false. If the game folder is not writable, it returns 1
   before reaching the elevation flow. The parent takes the online branch before its own
   write/elevation check. Therefore a normally launched setup can offer an update but
   cannot complete it on an installation requiring elevation. This is a control-flow
   finding; no UAC prompt or protected real installation was exercised.

   Carry the interactive update's elevation capability into the child, or elevate the
   verified child after checking the destination. Preserve the selected game path and
   propagate the final exit status. Test writable and protected fake destinations, approval
   cancellation, and quiet CLI behavior without creating unexpected prompts.

8. **A08 — Medium: package and manifest paths are not confined to the installation directory.**

   Source: [installer/src/main.cpp:234](https://github.com/matalvernaz/wandsong/blob/3d99313f0c376150b5c0edec0d1699b30e9b8787/installer/src/main.cpp#L234),
   [installer/src/main.cpp:491](https://github.com/matalvernaz/wandsong/blob/3d99313f0c376150b5c0edec0d1699b30e9b8787/installer/src/main.cpp#L491),
   and [installer/src/main.cpp:552](https://github.com/matalvernaz/wandsong/blob/3d99313f0c376150b5c0edec0d1699b30e9b8787/installer/src/main.cpp#L552).

   Package paths are normalized only by changing slash direction, then joined to Win64.
   Manifest entries are trusted similarly on removal. In `path_escape`, a payload entry
   named `../audit-marker.txt` wrote outside Win64 and uninstall deleted it there. The
   marker remained inside the disposable fake-game tree throughout the experiment.

   Reject parent traversal, absolute/rooted paths, drive prefixes and alternate data
   streams, and enforce containment after resolution, including reparse points. Validate
   manifest entries with the same policy. Check package sizes using subtraction-safe
   bounds against the payload end, excluding the footer. This is a package/local-file
   integrity weakness; the audit does not establish an unauthenticated remote exploit.
   An attacker-replaced executable is already executable code, so that is not the claim.

9. **A09 — Medium: installing an update silently disables vanilla mode.**

   Source: [installer/src/main.cpp:491](https://github.com/matalvernaz/wandsong/blob/3d99313f0c376150b5c0edec0d1699b30e9b8787/installer/src/main.cpp#L491)
   and [installer/src/main.cpp:571](https://github.com/matalvernaz/wandsong/blob/3d99313f0c376150b5c0edec0d1699b30e9b8787/installer/src/main.cpp#L571).

   Vanilla mode renames the loader to `dwmapi.dll.off`. A subsequent install writes a new
   `dwmapi.dll` without preserving that mode. `vanilla_update` confirmed that both files
   existed afterward and the active loader had returned. A later toggle still worked;
   the defect is the unexpected reactivation during the update.

   Capture the mode before updating, replace the appropriate active or inactive loader,
   and preserve that choice through rollback as well. Test install, vanilla toggle,
   update, launch-file state, and toggle back.

10. **A10 — Medium: refreshing a reordered menu list can activate an item the player did not select.**

    Source: [menus.lua:1104](https://github.com/matalvernaz/wandsong/blob/3d99313f0c376150b5c0edec0d1699b30e9b8787/mod/Wandsong/Scripts/menus.lua#L1104)
    and [menus.lua:1529](https://github.com/matalvernaz/wandsong/blob/3d99313f0c376150b5c0edec0d1699b30e9b8787/mod/Wandsong/Scripts/menus.lua#L1529).

    Review keeps the numeric index when the provider/screen stays the same. Press refreshes
    the list but checks selection continuity only if the top-level identity changes.
    In `menu_reorder`, the player reviewed the first destination; reversing the two items
    in the same provider made Press activate the second destination. Places is a practical
    consumer because its entries are rebuilt and sorted.

    Give entries stable identities and preserve/revalidate the selected identity through
    every refresh. If it disappears, announce the change and require a new selection.
    Cover reorder, insertion, removal and duplicate labels; travel confirmation must bind
    to the same destination identity.

11. **A11 — Medium: first-start enforcement reverses an explicit accessibility setting change.**

    Source: [gamesettings.lua:212](https://github.com/matalvernaz/wandsong/blob/3d99313f0c376150b5c0edec0d1699b30e9b8787/mod/Wandsong/Scripts/gamesettings.lua#L212)
    and [gamesettings.lua:248](https://github.com/matalvernaz/wandsong/blob/3d99313f0c376150b5c0edec0d1699b30e9b8787/mod/Wandsong/Scripts/gamesettings.lua#L248).

    Settings enabled automatically at startup remain in `set_this_start`. Turning one off
    through `M.toggle` does not clear that entry, so enforcement turns it back on before
    the first gameplay session. `settings_override` reproduced subtitles going on, then
    explicitly off, then back on at the next enforcement call.

    Treat an explicit choice as authoritative and remove that setting from automatic
    enforcement for the session. Keep any intended repair behavior for untouched settings.
    Test both paths and verify the spoken state matches the saved and effective setting.

12. **A12 — Medium: conflict detection forgets keys that remain active until restart.**

    Source: [bindings.lua:79](https://github.com/matalvernaz/wandsong/blob/3d99313f0c376150b5c0edec0d1699b30e9b8787/mod/Wandsong/Scripts/bindings.lua#L79)
    and [controls.lua:133](https://github.com/matalvernaz/wandsong/blob/3d99313f0c376150b5c0edec0d1699b30e9b8787/mod/Wandsong/Scripts/controls.lua#L133).

    The bindings used by gameplay are correctly captured at startup, but conflict
    detection reads only the edited file. In `pending_bindings`, changing a mapping from
    M to J on disk left its active binding at M while `conflict('M')` returned no conflict.
    Controls can then assign M to an immediately active mod action even though the game
    will still react to M until restart.

    Check both active and pending mappings, with an explanation of which conflict lasts
    until restart. Use a single canonical key representation. Test moving a game binding
    away from a key, assigning a mod binding during the same session, and restarting.

13. **A13 — Medium: hotspot interaction fails for supported nonletter remappings.**

    Source: [hotspots.lua:54](https://github.com/matalvernaz/wandsong/blob/3d99313f0c376150b5c0edec0d1699b30e9b8787/mod/Wandsong/Scripts/hotspots.lua#L54).

    The key observer compares a UE4SS enum name with an Unreal binding name. Names such as
    `DEL` and `Delete`, or `SPACE` and `SpaceBar`, are different even though they identify
    the same key. `hotspot_remap` configured Interact as Delete, made a hotspot available,
    delivered the normal `DEL` event, and observed no interaction call.

    Compare canonical virtual-key values or reuse the conversion already used by Controls.
    Cover letters, Delete, Space, punctuation and number keys. Also record a hotspot as
    used only after its interaction succeeds, so a transient failure remains retryable.

14. **A14 — Medium: walking to a selected positional quest marker ignores that selection.**

    Source: [scanner.lua:231](https://github.com/matalvernaz/wandsong/blob/3d99313f0c376150b5c0edec0d1699b30e9b8787/mod/Wandsong/Scripts/scanner.lua#L231)
    and [path.lua:892](https://github.com/matalvernaz/wandsong/blob/3d99313f0c376150b5c0edec0d1699b30e9b8787/mod/Wandsong/Scripts/path.lua#L892).

    For a scanner entry represented by coordinates rather than an actor path, the walk
    action calls general `walk_objective()` without the selected coordinates. In
    `scanner_marker`, the second of two markers was selected and correctly faced, but
    walking requested the general objective, whose destination was the first marker.

    Pass the selected point and label to a navigation operation that retains that target,
    or resolve it to the exact route marker. Test multiple markers, marker removal and
    changing the tracked quest between selection and activation.

15. **A15 — Medium: an actor reusing a memory address inherits the previous actor's identity.**

    Source: [world.lua:626](https://github.com/matalvernaz/wandsong/blob/3d99313f0c376150b5c0edec0d1699b30e9b8787/mod/Wandsong/Scripts/world.lua#L626).

    Nearby entries are keyed by address. Without an enabled lifetime serial, a fresh
    actor of the same category at an old address reuses the old snapshot, including its
    path and name. `reused_address` replaced a person between scans with a different
    person at the same address: the old path acquired the new position, while the new
    path was absent. The optional native lifetime tracking is off by default.

    Compare the fresh object's identity on every scan before reusing a snapshot, including
    its path and relevant class. Drop both address and path indexes when identity changes;
    clear actor-specific extra data and names. Preserve the fresh-scan architecture rather
    than adding unsafe lookups of old actor paths. Test address reuse between adjacent scans.

16. **A16 — Medium: an asynchronous UI load can strand the experimental AI walk's possession.**

    Source: [ai_walk.lua:231](https://github.com/matalvernaz/wandsong/blob/3d99313f0c376150b5c0edec0d1699b30e9b8787/mod/Wandsong/Scripts/ai_walk.lua#L231),
    [ai_walk.lua:114](https://github.com/matalvernaz/wandsong/blob/3d99313f0c376150b5c0edec0d1699b30e9b8787/mod/Wandsong/Scripts/ai_walk.lua#L114),
    and [world.lua:243](https://github.com/matalvernaz/wandsong/blob/3d99313f0c376150b5c0edec0d1699b30e9b8787/mod/Wandsong/Scripts/world.lua#L243).

    AI walking assumes every `state.loading()` event rebuilds the world and forgets its
    hand-back state. The world gate also marks asynchronous UI screen loading this way.
    In `ai_ui_load`, a load mark with the same world/pawn caused the walk to be forgotten;
    the pawn stayed AI-possessed after loading ended, and Stop could no longer restore it.
    This feature is disabled unless `ai_walk_enabled.txt` exists, which limits exposure.

    Distinguish a world transition from UI settling. For the same surviving world, retain
    hand-back state and restore control once object access is safe. On a true world change,
    discard old identities. Keep the feature opt-in until pause/open/close, failure, focus
    loss, cancellation and actual map loads have been verified in game.

17. **A17 — Medium: pending audio descriptions can cross into an unrelated loaded save.**

    Source: [subtitles.lua:360](https://github.com/matalvernaz/wandsong/blob/3d99313f0c376150b5c0edec0d1699b30e9b8787/mod/Wandsong/Scripts/subtitles.lua#L360)
    and [subtitles.lua:413](https://github.com/matalvernaz/wandsong/blob/3d99313f0c376150b5c0edec0d1699b30e9b8787/mod/Wandsong/Scripts/subtitles.lua#L413).

    Descriptions due soon after a recent cinematic are carried across any loading mark
    and resumed if another cinematic appears soon afterward. There is no continuity
    identity tying the carry to the original scene. `description_save_load` scheduled an
    old scene description, simulated loading another save with a new generation, and
    entered an unrelated silent scene. The old description was spoken there.

    Carry descriptions only across a recognized continuation, such as a known title-card
    transition, or require a matching new-scene anchor before resuming them. Explicit save
    loads and unrelated generation changes should cancel the carry. Test both the intended
    continuous scene transition and a different save opening in a cinematic.

18. **A18 — Medium: a spell checkpoint's announced fallback starts full assistance instead of answering it.**

    Source: [spells.lua:93](https://github.com/matalvernaz/wandsong/blob/3d99313f0c376150b5c0edec0d1699b30e9b8787/mod/Wandsong/Scripts/spells.lua#L93)
    and [spells.lua:466](https://github.com/matalvernaz/wandsong/blob/3d99313f0c376150b5c0edec0d1699b30e9b8787/mod/Wandsong/Scripts/spells.lua#L466).

    `option_key` announces the mod's Press key for options 77/78 when the binding has no
    usable keyboard key. `M.press` only sends a checkpoint action for codes 79 or higher.
    In `spell_checkpoint_fallback`, option 77 was mouse-only: its instructions returned
    the Press fallback, but Press sent no checkpoint action and enabled full tracing
    assistance instead. The player did not ask to change the lesson mode.

    Base activation on the same fallback decision used to announce the key, including
    options 77/78. Honor actual remapped keyboard keys for all options. Test keyboard,
    mouse-only and unbound mappings across all four checkpoint codes.

19. **A19 — Medium: stopping all audio does not stop an already playing one-shot.**

    Source: [native/audio_bridge.cpp:358](https://github.com/matalvernaz/wandsong/blob/3d99313f0c376150b5c0edec0d1699b30e9b8787/native/audio_bridge.cpp#L358).

    Loop voices are stopped/destroyed, but one-shot voices receive only
    `FlushSourceBuffers()`. On a started voice, that operation retains the currently
    playing buffer and does not stop playback. Therefore a cue already playing can finish
    after mute or a scene transition. This follows from the implementation and
    [Microsoft's documented XAudio2 behavior](https://learn.microsoft.com/en-us/windows/win32/api/xaudio2/nf-xaudio2-ixaudio2sourcevoice-flushsourcebuffers);
    no audible device-level reproduction was performed.

    Stop each one-shot voice, flush it with the documented state handling, and restart it
    when reusing it. Verify immediate mute during a long preview and successful playback
    afterward, including rapid mute/unmute and repeated scene changes.

20. **A20 — Low: Enter cannot activate an open mod screen while gameplay remains active.**

    Source: [menus.lua:1546](https://github.com/matalvernaz/wandsong/blob/3d99313f0c376150b5c0edec0d1699b30e9b8787/mod/Wandsong/Scripts/menus.lua#L1546).

    The Enter action returns whenever `world.gameplay()` is true, without first allowing
    a virtual mod screen. `virtual_enter` opened a mod provider during gameplay: Enter
    did nothing, while the dedicated Press key activated the selected item.

    Allow Enter for an active mod screen before applying the gameplay guard. Retain the
    text-editing and native popup protections. Test Controls, Places and the guide during
    gameplay, a text field, and a game popup that already consumes Enter.

Several improvements would address the causes of these findings and make future changes
easier to verify:

- **Make installation recoverable first.** A01-A03 share a need for complete ownership
  records, checked writes and rollback. Include A08-A09 in the same installer design work,
  while retaining separate regression cases for each behavior. Preserve backups until
  verified recovery succeeds; installation success must include a usable manifest.
- **Give load reasons and object access explicit semantics.** A05, A06, A16 and A17 all
  depend on a shared loading flag representing several different situations. Represent
  world replacement, UI settling, pause and tick loss distinctly, with a clear generation
  transition and rules for what each timer may touch. Retain the existing protection
  against object access when the game thread is genuinely inside a load.
- **Use stable identity for actions and snapshots.** Bind menu selection and travel
  confirmation to an entry ID. Compare fresh actor identity before refreshing an address
  slot. Resolve only the specific selected button's delegate. These changes can remain
  local; a rewrite of the runtime is unnecessary.
- **Unify binding conversion and expose pending state.** There are multiple key-name
  representations across bindings, Controls, observers and spell actions. Centralize
  conversion and test round trips. Say which changes need a restart, check active and
  pending conflicts, and add movement-axis controls to the accessible remapping menu:
  `read_game()` currently reads only recognized `ActionMappings`, despite the guide's
  broad claim that the game's keys can all be changed there.
- **Make settings writes reliable and preferences explicit.** The Controls writer opens
  `Input.ini` directly for truncating writes and does not check every write/close result.
  Use a temporary file, verified backup and atomic replacement. Persist user-facing
  toggles where consistency across launches is intended, and distinguish temporary mute
  from a saved preference. Test a read-only configuration and a failed write without
  damaging the prior file or announcing a successful change.
- **Expand CI around the actual shipped product.** The workflow runs Lua tests and builds
  the input bridge, but does not build/test the complete installer/helper/audio/click/
  speech release path. Add all native targets, the fake-game setup suite and relevant
  failure cases. Parse every tracked maintenance script. Gate packaging/publishing on
  tests of the exact build being released. Existing deterministic tests are useful, but
  several mocks do not reproduce long tick gaps, file sharing failures or identity reuse.
- **Measure frame cost where scans accumulate.** For example, `quest_widgets()` performs
  two global widget searches in one callback, while the runtime's own comments estimate
  substantial per-search cost. Record timer duration and worst/p95 frame contribution;
  distribute optional scans across frames and reuse safe scalar snapshots. Profile menu
  traversal, navigation rays and world scans together on a dense scene before choosing
  scan limits. No new performance benchmark was taken in this audit.
- **Harden native lifecycle handling.** Add device-loss/reinitialization handling and a
  defined shutdown path for audio. Exercise speech backend disappearance/reappearance and
  make failed output fall back or retry observably. Review delegate broadcasts when a
  callback destroys its widget or changes the binding list. Retain pinned native ABI
  compatibility and fail safely when required exports/layout assumptions are absent.
- **Record dependency provenance.** The build pins version tags, but cached dependencies
  are reused based on file existence and downloaded artifacts are not verified against
  committed expected hashes. Record exact artifact hashes and supported compiler/runtime
  versions, verify cached content, and include them in release metadata. Do not change
  the embedded Lua ABI independently of the supported UE4SS build.
- **Strengthen description data validation.** Validate nonempty text, finite ordered
  timings, duplicate/ambiguous IDs and expected scene anchors during generation. Keep
  recordings and observed game IDs tied to the tested locale/version. Test save loads,
  skips, changed player voice and repeated short dialogue separately from text similarity.
  Full-playthrough and non-English description coverage remain product work, not something
  the current offline suite proves.
- **Update the contributor and player documentation.** The maintained test count and
  testing/deployment descriptions have fallen behind the code. Document shipped versus
  opt-in features, available fallbacks, expected restart behavior and the actual validated
  game scenarios. Parameterize hardcoded game paths in developer helpers, and give setup
  tests unique temporary directories so concurrent runs do not erase one another's work.

The following risks merit targeted verification but are **not included in the 20 confirmed
findings**:

- Generic checkbox activation uses `SetIsChecked` without an explicit game change
  callback. The local SDK exposes the setter and change delegate separately, but a real
  game test is needed to determine which affected settings persist correctly.
- Native delegate broadcasting iterates the live delegate array while callbacks can
  potentially mutate it. Inspect or test callback-driven removal/destruction before
  claiming a demonstrated use-after-free. A defensive snapshot of weak handles is worth
  considering.
- Held synthetic keys depend on Lua-driven cleanup. Test a stalled dispatcher, lost focus
  and module teardown for stuck keys; consider an independent release timeout if needed.
  The audit did not deliberately hang the real game or inject keys to establish this.
- Speech backend switching, braille output, Unicode installation paths, unusual Windows
  audio layouts, denied elevation and interrupted online downloads need integration tests.
  Successful compilation does not prove those device/system combinations work.

Recommended implementation order is A01-A03 and A08-A09 for installer integrity; A04-A06
for menu/load safety; then A07 and A10-A20 with their individual regression cases. Add CI
coverage alongside each fix, rather than merely adding the current bad-behavior probes to
the passing suite.

Before calling the resulting build validated in game, exercise a pause menu lasting at
least ten seconds, failure/retry, fast travel, save loading during a cinematic, repeated
menu open/close, scene transitions during sound playback, remapped punctuation/number
keys, a reordered Places list, multiple quest markers, and spell checkpoints. Check that
screen reader output remains useful throughout. AI possession requires its own opt-in
test with a verified return of player control; the audit provides no basis for enabling
it by default.
